6.graph LR
    API[🌐 API Communication System]
    
    %% Branch 1: The Request flow
    API --> Flow[📍 The Request Flow]
    Flow --> Client[1. Frontend requests data]
    Flow --> Router[2. Router maps URL to controller]
    Flow --> AH_Wrap[3. asyncHandler wraps controller]
    Flow --> Ctrl[4. Controller talks to Database]

    %% Branch 2: Success path
    API --> Success[💚 The Success Path]
    Success --> ApiResponse[📦 ApiResponse.js]
    ApiResponse --> S_Role[Role: The Standard Plate]
    ApiResponse --> S_Desc[Ensures every successful response is formatted exactly the same]
    ApiResponse --> S_Keys["Key variables: statusCode, message, data, success (true)"]

    %% Branch 3: Failure path
    API --> Failure[❤️ The Failure Path]
    Failure --> ApiError[⚠️ apiErrors.js]
    ApiError --> E_Role[Role: The Standard Complaint Card]
    ApiError --> E_Desc[Adds web status codes to default JS errors so frontend understands what failed]
    
    Failure --> AsyncHandler[🛡️ asyncHandler.js]
    AsyncHandler --> A_Role[Role: The Chef's Safety Net]
    AsyncHandler --> A_Desc[Listens for database crashes and safely catches them]
7.asyncHandler.js:It wraps your async functions. If your database crashes or query fails, it catches the error and sends it to Express's global handler, preventing the server from crashing.
apiResponse.js:Creates a beautiful, standard JSON template for success (e.g. { statusCode, data, message, success: true }). Every single successful page load looks identical.
apiErrors.js:
Extends the basic JS Error class to attach HTTP Status Codes (like 400, 401, 404) and standard message formats so the frontend knows exactly why it failed.
   Depending on the outcome, the server wraps the result in ApiResponse (for success) or ApiError (for failure) so the user gets a perfect, readable final message!

Some hooks : Pre = jaise hi data save hone wala hoga,usse just Pehle koi code run krwa skta h
syntax: userSchema.pre("functionality", callback()=>{}){},functionality like save,validate,etc
how to use:(code)=//hooks
userSchema.pre("save", async function (next) {
    if (!this.isModified("password")) return next();
    this.password = await bcrypt.hash(this.password, 10);
    next();
})
//methods or custom methods
userSchema.methods.isPasswordCorrect=async function(password){
    return await bcrypt.compare(password,this.password)
}
what is does is that "pre" hook before saving ,encrypt the password using bcrypt library,since it takes some time it is a async function,next is the flag that it encrypted or not,encrypt by the function bcrypt.hash(object,rounds),rounds are the algorithm to encrypt the password
Then to check if the DB password matches the password here using custom method

Most Common Headers: $ Accept        CORS:
$ User                               Access-Control-Allow-Origin
$ Authorization                      Access-Control-Allow-Credentials

HTTPS METHODS:Basic set of ops that can be used to interact with server
$ GET:retreive data from server
$ POST:create or send data to server
$ PUT:update entire data
$ PATCH:update specific data
$ DELETE:delete/remove data
$ HEAD:fetches the headers only,not the body
$ OPTIONS:ask server which methods are allowed
$ TRACE:request /loopback test(get same data)
